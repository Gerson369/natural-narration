# Clarity Engine｜清晰度引擎（v0.3.0 新增）

v0.2.0 已经有 Clarity 分数，但只看句长。这份文件把「讲清楚」拆成可执行的五项检查。

目标不是句子更短，而是：**听一遍就懂，不用倒回去。**

## 1. 核心判断测试

一条内容只能有一个主判断。

- 必须能用一句普通话说出来。
- 不能只是：很重要 / 值得思考 / 给我们启示 / 带来巨大影响 / 改变认知 / 提升自己。
- 主判断出现的位置越早越好，最迟不晚于全文三分之一处。

如果写完之后说不出主判断，问题在内容，不在语言。

## 2. 一句一任务

一句话不要同时承担：提出观点 + 解释原因 + 举例 + 转折 + 总结 + 升华。

- 单个分句超过 28 字，通常已经装了两件事，拆开。
- 拆开不等于拆碎：拆完仍要满足字幕行 12–24 字（见 `rhythm-rules.md`）。
- 禁止把一句话拆成转折词、数字、半句话独立成行。

**差**：因为表达能力其实决定了你能不能被看见，而被看见又决定了机会，所以这件事比努力更重要。

**优**：说不清楚，机会就不会来找你。这一点常常比多做一件事更关键。

## 3. 指代检查

重点检查这些词：这、它、这种情况、这个问题、这个方法、这种能力、这件事。

判定：听众在**听到这个词的那一秒**能不能说出它指什么。不能，就换回名词。

**差**：这种能力一旦建立起来，它会持续影响后面的所有事情。

**优**：能把复杂的事讲成三句话，这个习惯会一直帮你省时间。

## 4. 抽象词落地

出现下面这类词不必删除，但必须有具体含义跟上：

价值、成长、能力、认知、思维、系统、底层、维度、格局、长期主义、复利、闭环、赋能、抓手。

落地方式：改成一个可观察的差别、一个动作或一个数字。

- 「提升认知」不算清楚。
- 「知道收入增加和利润增加不是一回事」才算清楚。

硬指标：抽象句占比过高、或连续 4 句以上不落地 → 触发 `story-engine.md` 的 Concrete Scene Router。

## 5. 删除后是否还能成立（Explanation Test 升级版）

把金句、反问、情绪词、修辞、故事全部删掉，只留信息句，然后确认三件事：

1. 核心判断仍然清楚。
2. 因果链仍然完整。
3. 动作与边界仍然可执行、可验证。

撑不住 → 回到事实层重写，不要补更多修辞。

这是内部检验，成稿仍然保留钩子与口语节奏，不允许因此把稿子洗成百科（见 `anti-overcorrection.md`）。

## 对应的硬指标

`nn_scan.py` 输出的 value 行提供代理指标：

| 指标 | 含义 | 参考阈值 |
| --- | --- | --- |
| `long_clause` | 超长分句数量 | 短稿 ≤ 1 |
| `unresolved_ref` | 疑似指代不明的句子 | ≤ 1 |
| `generic_value` | 空泛价值句命中 | 0 |
| `vague_action` | 模糊行动词命中 | 0 |
| `repeated_conclusion` | 同一结论反复重说 | ≤ 1 |
| `boundary_marker` | 限定与边界表达数量 | ≥ 1（方法论类） |
| `clarity_plus` | 清晰度合成分 | ≥ 8 |

脚本只能判断形式，不能判断「主判断是否明确」「证据是否支持判断」。这两项由语义审稿完成，属于人 / 模型门禁，不写成数字。
