# Story Engine｜故事引擎（v0.2.0 新增）

三层检测解决的是「不像模板」。故事引擎解决的是「值得听下去」。

判断标准：**这段话是在解释一件事，还是让这件事在观众眼前发生？**

只解释也能通过语言层检测，但会得到「非常自然、非常准确、非常清楚，却像一个懂行的人在讲课」的稿子。故事层负责补上这一段。

硬边界写在最前面：故事化只允许重新组织**已有事实**，不允许补充没有资料支撑的细节。

## 五个引擎

### 1. 叙事主体 Subject

每一段都要知道跟着谁走。可选主体：你、光、空气、水、星系、数据、仪器、观测者、当事人、材料、电流。

- 差：这项研究说明温度极高。
- 优：电流穿过那条通道时，里面的空气被瞬间加热。

禁止全篇只有「知识」在场，没有任何主体。

### 2. 场景起点 Scene Entry

故事要从一个可以看见的位置开始，而不是从一个结论开始。

- 可用起点：某个具体时刻、某个地点、某个动作、某个被观察到的异常。
- 抽象观点如果必须先出现，下一句就要落到场景。

### 3. 状态变化 State Change

一段内容至少要交代：开始是什么状态 → 中间发生了什么 → 之后什么被改变了。

没有状态变化的段落，本质上只是定义。

### 4. 发现路径 Discovery Path

人们怎么注意到异常、怎么排除误差、怎么一步步接近答案。

只允许写**有资料支持**的过程。禁止编造「科学家一开始以为设备坏了」「他当时心里想」这类戏剧细节。资料不足时，写「早期研究先注意到 X，随后才确认 Y」，或者直接省略。

### 5. 视角移动 Camera Move

整篇不能一直站在同一个位置解释。视角可以在这些位置之间移动：

- 地面 ↔ 高空 ↔ 轨道
- 肉眼 ↔ 仪器 ↔ 数据
- 一瞬间 ↔ 几百万年
- 结果 ↔ 发生过程
- 个体 ↔ 群体

每次移动都要有信息价值，不做纯炫技的镜头切换。

## Concrete Scene Router｜抽象 → 具体路由

触发条件：连续 3 句以上没有场景、动作、时间或数字。

触发后，必须从下面六项里补进至少一项：

1. 真实案例
2. 具体动作
3. 时间限制
4. 空间场景
5. 一次选择与它的后果
6. 可核实的亲历经历

例（方法论类）：

- 差：表达能力决定了你的机会上限。
- 优：在电梯里遇到投资人，只有三到五分钟，说不清楚这件事就没有下一次会面。

## 与自然推进模型的关系

故事引擎挂在 `natural-narration-model.md` 的推进顺序之上，**不引入**悬念、反转、伪金句、升华。

- 允许：主体、场景、动作、状态变化、视角移动。
- 不允许：为了故事感制造误解、制造悬念、制造反转、编造心理活动。

两者冲突时，事实优先，其次自然，最后才是故事感。

## 故事层自检（4 项）

- [ ] 每段都有明确主体，不是只有「知识」在场
- [ ] 全文至少有一个可以看见的具体场景
- [ ] 至少有一处状态变化（之前 → 之后）
- [ ] 抽象段落没有连续 4 句以上不落地

检测器对应指标：`story_strength`、`scene_ratio`、`action_ratio`、`abstract_ratio`、`max_abstract_streak`。

```bash
python3 scripts/nn_scan.py draft.txt --story-gate
```

叙事 / 人物 / 纪录片 / 方法论类任务建议加 `--story-gate`（Story Strength ≥ 6 才算 PASS）。纯定义类、纯清单类内容不加这个门禁。
