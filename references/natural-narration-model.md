# Natural Narration 模型

## 自然推进顺序（默认）

事实 → 动作 → 原因 → 结果 → 数字 → 时间 → 尺度 → 限制条件 → 下一个事实

不默认使用的推进顺序：

误解 → 否定 → 悬念 → 反问 → 揭晓 → 反转 → 金句 → 升华

## 开头钩子只从这七个地方取

1. 明确结果：已经发生了什么。
2. 极端数字：温度、速度、质量、距离。
3. 时间：多久、哪一年、持续多久。
4. 尺度：比什么大、占多少比例。
5. 后果：对人、对环境、对设备意味着什么。
6. 具体场景：你能看到什么、听到什么。
7. 真正的反常事实：与常识不同且有资料支撑。

例：“闪电经过的那一小条空气，温度可以瞬间冲到三万摄氏度左右。”
这已经是强钩子，不需要再加“而更可怕的还在后面”。

## 事件化：把知识写成正在发生的事

- 不写“研究表明……”，写“电流经过时，空气被拉开、被加热、向外膨胀。”
- 每一段都要知道主角是谁：你、光、空气、探测器、数据、观测者。
- 写“如果……”就必须继续写“然后呢”，并标明是假设。
- 视角可以移动，但不拟人化成煽情；拟人只用于让真实物理过程可见。

## 人物类附加规则

- “值得学什么”要具体到动作、习惯、笨功夫，不写“思维方式、底层逻辑”。
- 不神化人物，不把复杂成就归因为单一原因。
- 只写有资料支持的细节，不编造心理活动和现场对话。

## 哲学 / 认知类附加规则

- 先给普通人真实痛点，再给问题命名，再给一个克制准确的判断。
- 抽象概念必须落到可观察的具体情境。
- 结尾可以是一个自查问题，但不升华成宇宙哲理。

## 纪录片类附加规则

- 时间线优先，不靠悬念推进。
- 不确定的地方直接说不确定，用“大约、常见资料提到、目前证据显示”。

## 与故事引擎的关系（v0.2.0）

推进顺序负责“讲得清楚”，故事引擎负责“值得听下去”。两者是叠加关系，不是替代关系。

- 推进顺序不变：事实 → 动作 → 原因 → 结果 → 数字 → 时间 → 尺度 → 限制条件 → 下一事实。
- 故事引擎在这个顺序之上补五件事：叙事主体、场景起点、状态变化、发现路径、视角移动。
- 故事引擎不引入悬念、反转、伪金句和升华，它只让同一批事实变得可看见。

详见 `story-engine.md`。判断一段内容属于哪一层，可以问：这段是在解释一件事，还是让这件事在观众眼前发生？

## 价值链接入推进顺序（v0.3.0）

原模型解决的是「怎么说」，价值链解决的是「说什么才值得听」。两者的先后关系是固定的：

1. 先跑价值链六问（真实问题 → 核心判断 → 事实或案例 → 实际影响 → 可执行动作 → 适用边界）。凑不齐四项就不开写，回到选题层。
2. 再用推进模型安排顺序：具体开场 → 扩展事实 → 因果推进 → 信息收尾。核心判断放在开场之后、事实之前。
3. 每个推进段落都要能回答「这段在价值链上占哪一环」。回答不了的段落删掉。
4. 边界不放结尾做免责声明，就跟在判断后面，否则听众已经把结论当普适规律了。

与层级冲突时的让步顺序：事实 > 清晰 > 自然 > 故事感。为了故事感而牺牲清晰度，是 v0.3.0 明确禁止的。
