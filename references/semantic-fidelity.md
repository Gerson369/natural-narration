# Semantic Fidelity｜语义保真层（v0.5.0）

去 AI 味不能以改变原意为代价。数字保住了，意思仍可能被改掉：「可能有关」变成「就是因为」，「计划周五」变成「周五已发布」，「供应商声称」变成事实陈述。这一层专门拦截这类改写。

## 适用范围

- MODE B CLEAN：必须执行。
- MODE A WRITE：用户提供素材、采访稿、研究摘要时，对素材中的判断执行同样检查。
- FILE MODE：在正文部分执行，结构部分见 `file-mode.md`。

## 第一步：锁定语义锚点（改写前）

通读原稿，在内部列出七类锚点。每一类都是信息本身，不是语气。

| 锚点 | 识别信号 | 常见错误改写 |
| --- | --- | --- |
| `NEGATION` 否定 | 不、没有、未、尚未、并非、无法、不能 | 「尚未确认」被删成「确认了」或直接消失 |
| `MODALITY` 确定程度 | 可能、或许、大概、据称、疑似、目前看来 | 「可能」改成「确定 / 就是 / 一定」 |
| `STATUS` 状态 | 正在、计划、准备、将、已经、完成、尚未开始 | 「计划」改成「已经」，「正在测试」改成「测试完成」 |
| `CONDITION` 条件 | 如果、只有……才、除非、前提是、一旦、否则 | 前提被删掉，条件句变成无条件断言 |
| `SCOPE` 范围 | 至少、超过、不到、仅、只、部分、其中、大约、左右、最多 | 「超过 1200 人次」改成「1200 名观众」 |
| `ATTRIBUTION` 归因 | 认为、声称、表示、指出、据、报告、称 | 「供应商声称」改成「这项服务能」 |
| `CAUSALITY` 因果 | 有关、相关、伴随、同时出现 vs 导致、造成、因为、所以 | 相关被升级为因果 |

另加一类原有锚点：数字、单位、尺度词（v0.1 起由 Information Preservation 检查）。

## 第二步：改写

改写时只动表达，不动锚点。允许：

- 换说法但保留同一强度：「尚未确认」→「还没确认」。
- 合并句子但保留各自的条件和归因。
- 把被动改主动，前提是施事者在原文中已经明确。

不允许：

- 删除否定、条件、范围词来让句子「更有力」。
- 把被归因的观点改写成叙述者自己的断言。
- 为了节奏把「正在 / 计划」并入「已经」。
- 补出原文没有的施事者，例如凭空写出「研究人员」「系统」「团队」。

## 第三步：逐项比对（改写后）

对每类锚点回答一个问题：

1. 否定还在吗？
2. 确定程度有没有被拔高？
3. 正在、计划、完成的状态一致吗？
4. 条件和前提还在吗？
5. 至少、超过、仅这类范围词一致吗？
6. 观点仍然归在原来的人或机构名下吗？
7. 相关有没有被写成因果？

任一项答「否」，回到第二步补回。

## 判定与门禁

- Semantic Fidelity 满分 10，每类出现问题扣 2 分。
- 通过线：Semantic Fidelity ≥ 9。
- 零容忍：否定丢失 = 0，确定性拔高 = 0，状态改变 = 0，归因丢失 = 0。
- 脚本：`python3 scripts/nn_scan.py --baseline before.txt --after after.txt --fidelity-gate`。

脚本按锚点词计数做比对，是代理指标：

- 改写换了同义词（「尚未」→「还没」）时，脚本按同组词计数，不误报。
- 脚本无法判断「可能」修饰的对象是否被换掉，仍需模型做语义核对。
- 脚本 PASS 不等于语义完全一致；脚本 FAIL 一定要回查。

## 与其他层的关系

- 与 Evidence Arc：Evidence Arc 决定证据怎么推进判断；语义保真决定改写时不能偷偷加强判断。两者冲突时，以原文证据强度为准。
- 与价值链：价值缺环只提示，不补写；补写会同时破坏价值链规则与语义保真。
- 与说服腔：把条件降级为承诺，同时命中 H 类与本层。

## 示例

**原稿：** 社区多次报告这个问题，被认为可能与内存泄漏有关，但原因尚未确认。

**错误改写：** 这个问题就是内存泄漏导致的。

- 丢失 `NEGATION`（尚未确认）
- `MODALITY` 拔高（可能 → 就是）
- `CAUSALITY` 升级（有关 → 导致）
- `ATTRIBUTION` 丢失（被认为）

**合格改写：** 社区多次报告这个问题。有人认为可能和内存泄漏有关，原因还没确认。
